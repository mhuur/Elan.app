# Élan — Suivi sport

App PWA mobile-first de suivi sportif (running, vélo d'appartement, muscu, HIIT, étirements). UI en français, design vert sauge/crème.

## Commandes

- `npm run dev` — serveur de dev (http://localhost:5173), mode cloud si `.env` rempli
- `npm run dev:demo` — serveur en mode local forcé (port 5174, `.env.demo` vide les clés Firebase)
- `npm run build` — tsc + vite build vers `dist/`
- `node scripts/smoke.mjs` — test de fumée Playwright (lancer `dev:demo` avant), captures dans `screenshots/`
- `node scripts/check-alternance.mjs` / `check-interval.mjs` / `check-v4.mjs` / `check-blocs.mjs` / `check-form-ui.mjs` / `check-player-reps.mjs` — vérifs Playwright ciblées (alternance, intervalle, objectifs à paliers, blocs muscu, formulaires épurés, réalisé dans le minuteur), aussi sur `dev:demo`
- `node scripts/check-cloud.mjs` — vérifie l'écran de connexion Google sur 5173
- `node scripts/make-icons.mjs` — régénère les PNG PWA depuis `public/icon.svg`

Le `.env` (gitignoré) contient la config Firebase du projet `routine-sport-ca440` de l'utilisateur.

## Environnement

Node.js est installé en **portable** (pas de droits admin sur cette machine) dans
`%LOCALAPPDATA%\Programs\node-v24.16.0-win-x64`, ajouté au PATH utilisateur.
Si `node` est introuvable dans un shell : `$env:Path += ";$env:LOCALAPPDATA\Programs\node-v24.16.0-win-x64"`.
Ne jamais lancer d'installation nécessitant une élévation UAC (winget MSI, etc.).

## Architecture

- **Double mode de stockage** (`src/data/store.ts`) : interface `Store` avec `LocalStore` (localStorage, par défaut sans `.env`) et `FirestoreStore` (`users/{uid}/exercises|sessions|logs|ideas`). Le mode est choisi dans `src/firebase.ts` selon la présence des variables `VITE_FIREBASE_*` dans `.env`. La collection `ideas` (bugs & idées saisis dans Réglages) ne bloque jamais `dataReady` et dégrade en liste vide si les règles Firestore la refusent.
- `src/data/DataContext.tsx` : provider unique (auth Google + abonnements aux 4 collections + CRUD + seed au premier lancement via `src/data/seed.ts`, gardé par un flag localStorage `elan-seeded-*`).
- Types et métadonnées de catégories (couleurs/emoji/classes Tailwind) : `src/types.ts`.
- Jours de semaine indexés **0 = lundi … 6 = dimanche** (`src/lib/dates.ts`), dates de logs en `YYYY-MM-DD` local.
- Planification : jours fixes (`Session.days`) OU intervalle (`Session.repeat` = tous les X jours + date de départ + rotation par jours). La rotation est `repeat.steps: { ids: string[] }[]` : chaque étape regroupe les séances d'un MÊME jour (ex. [Pompes+Abdos] puis [Jambes+Dos]), `occurrence % steps.length` choisit l'étape (tableau d'objets car Firestore refuse les tableaux imbriqués ; les anciens champs `alternates`/`alternateWith` sont normalisés par `cycleStepsOf()`). Le cycle est porté par UNE séance « propriétaire » ; les membres se détectent via `ownerOf()` et l'éditent depuis leur fiche (réécriture du propriétaire dans `SessionForm.applySchedule`, qui nettoie aussi `repeat` ET `days` des membres et répare les anciens cycles « bidirectionnels »). À la lecture, `canonicalCycles()` (`src/lib/schedule.ts`) garantit qu'une séance n'appartient qu'à un seul cycle (premier propriétaire gagne) et les jours fixes des membres sont ignorés. `repeat: null` / `objective: null` / `goal: null` (et non undefined) pour désactiver — Firestore ne supprime pas les champs absents d'un update.
- Objectifs **à paliers avec récompenses** : `Exercise.goal.levels[]` (meilleure série/volume muscu) et `Session.objective.levels[]` (chaque palier = cibles multi-mesures à remplir dans une même séance + `reward`). Normalisés par `goalLevels()` / `objectiveLevels()` dans lib/metrics (gèrent les anciens formats `value`/`targets`). Gérés dans l'onglet `/goals` (création, modification ✎, suppression), célébrés à la complétion (CompleteSheet) **uniquement pour les paliers nouvellement franchis** (la récompense ne se débloque qu'une fois).
- L'écran Aujourd'hui navigue dans les dates passées (saisie rétroactive) : `CompleteSheet` accepte une prop `date`.
- Sémantique par sport : running = simple coche ; vélo = formulaire perfs (préremplies depuis le dernier log, programme prévu affiché à l'avance via `MetricDef.target`) ; muscu = séries×reps (exercices `measure: 'sec'` pour le gainage), avec **séries variées** possibles (`SessionItem.targets: number[]`, ex. 30/20/15, normalisé par `setTargetsOf()` dans types.ts qui prime sur `target`) ; HIIT/étirements/muscu = minuteur guidé `src/pages/Player.tsx` (WebAudio + vibration + wake lock ; en muscu les séries en reps s'ajustent en − / + puis « Série faite ✓ », le gainage et les repos sont chronométrés). Le Player journalise le **réalisé réel** (`doneRef`, muscu ET HIIT) : reps ajustées, durée cible si chrono tenu, temps écoulé si « Passer » ≥ 3 s ; séries « **mal réalisées** » marquables pendant la séance — bouton « Série ratée ? » sur l'écran de repos (dernière série, `lastSetRef`) et tap sur une ligne travaillée du tiroir programme (bascule toutes les séries enregistrées de l'exo, ⚠ ambre). Commandes du Player : ✕ = quitter SANS enregistrer ; ■ = arrêter ici (confirm + prompt commentaire, log partiel, note « Séance interrompue » par défaut) ; **touche espace** = pause/reprise (démarrage sur l'écran prêt), label « En pause » + anneau en pulsation ; **mode immersif sombre** (fond `#161b17`, teinte bleutée au repos, accents lumineux par catégorie via `ACCENT`/`CALM`) : barre de progression globale sous le header, **anneau de progression** central (`Ring`, fraction restante `frac` rafraîchie ~10×/s ; piste seule pour les reps manuelles, − / + autour de l'anneau), **écran de repos dédié** avec carte « Prochaine série » (nom · série · objectif), commandes ■ / pause (blanche) / ⏭ regroupées au-dessus du **tiroir programme** : résumé permanent « Bloc 2/3 · Tour 1/2 » + « Ensuite : X », liste complète blocs/tours/exos dépliée au tap (`aria-label="Programme"`, ✓ faits / › courant accentué, prescriptions `itemLabel` à droite, auto-scroll, position via `Step.block/round/item`) ; détail central limité à « Série s/n » + pilule « démo » si l'exercice courant a une videoUrl. **CompleteSheet (Aujourd'hui) = consulter / lancer / entrer le résultat uniquement** : programme muscu en lecture seule structuré par blocs/tours (« Bloc 2 · × 2 tours », résumé « 3 × 20 reps » ou « 30 / 20 / 15 reps ») ; « Entrer le résultat ✓ » (muscu **et HIIT**) ouvre la **timeline à curseur** : toutes les séries dans l'ordre réel d'exécution, groupées par bloc/tour (en-têtes « Bloc b · Tour r/n »), tap sur une ligne = « je me suis arrêté ici » (elle et toutes les suivantes passent en non faites, exclues du log ; re-tap sur une non-faite la refait et requalifie ce qui précède), icône ⚠ par ligne = « **mal réalisée** » (`ExerciseResult.flagged` = indices dans `sets` ; annotation pure, la valeur compte quand même dans volume/paliers, affichée dans `logSummary`), sans steppers ni ajout/retrait de série — les valeurs journalisées sont les cibles. Le bouton de complétion s'appelle « Valider la séance ✓ » (+ « Fermer sans valider »).
- **Blocs** (`src/lib/blocks.ts`, muscu ET étirements) : une séance se découpe en blocs d'exercices répétés indépendamment (`SessionItem.blockBreak` démarre un bloc, `blockRounds` = ses tours, posés sur le 1er exercice du bloc). Sans découpage, un seul bloc avec `Session.rounds` (« Tours du circuit » muscu / « Tours de la routine » étirements). Utilisé par CompleteSheet (programme et saisie par tours) et le Player ; le superset reste muscu-only. `stretchTotalSec` (format.ts) compte blocs et tours. Dans la fiche séance, **les blocs entiers se déplacent au drag & drop** par la poignée de leur en-tête (ids `blk-{uid}` dans un SortableContext de blocs, items dans un SortableContext par bloc, un seul DndContext ; déplacer la tête d'un bloc transfère le bloc à l'exercice suivant).
- **Étirements : `Exercise.measure` est respectée** — posture tenue (`sec`, défaut du seed/quickCreate/ExerciseForm pour cette catégorie) = `durationSec` chronométré ; mouvement compté (`reps`) = `SessionItem.target`, étape manuelle « Fait ✓ » dans le Player et « N reps » dans le programme. Bascule sec/reps dans la ligne d'item (modifie l'exercice globalement). Les anciens exercices d'étirements créés en `reps` par défaut s'affichent désormais en répétitions : un tap sur la bascule les corrige.
- Planning : sections personnalisées via `Session.group` (champ « Section du planning » de la fiche, drag & drop entre sections) ; ronds de la semaine = anneau « prévu » / plein « fait » ; **toucher un rond valide/dévalide la séance ce jour-là (crée/supprime un log)** — la grille ne modifie jamais la planification, qui s'édite dans la fiche.
- **Formulaires épurés** (demande utilisateur, juin 2026) : les fiches séance/exercice n'affichent plus de murs de chips — catégorie en `Select`, section du planning et sous-types via `Combobox` (`src/components/ui.tsx` : saisie → filtre (label OU groupe) → « + Créer » en fin de liste si aucune correspondance exacte ; en-têtes de groupes via `option.group` en bandeau sage, panneau en z-50 au-dessus de la barre d'action). Les exercices d'une séance s'ajoutent/créent par la même combobox (groupée par sous-type) ; chaque item = carte blanche compacte avec saisie directe `MiniNum` (séries × cible + bascule reps/sec + bouton « Varier les séries » + repos), sous-type affiché en gris, et **réordonnancement par drag & drop** (dnd-kit, poignée GripVertical ; les items reçoivent un `uid` transitoire retiré à la sauvegarde). Le formulaire de séance n'édite plus `metrics`/`links`/`notes` : ils sont **préservés tels quels** à la sauvegarde (le vélo retombe sur `DEFAULT_VELO_METRICS` via `effectiveMetrics`) et toujours affichés dans CompleteSheet s'ils existent. Boutons Enregistrer/Dupliquer/Supprimer regroupés dans `FormActions` (barre fixe en bas) ; la BottomNav est masquée sur `/session/*` et `/exercise/*` (`formScreen` dans App.tsx).
- **Charte minimaliste** (juin 2026) : icônes **lucide-react** partout — y compris les catégories via `CategoryIcon` (`ui.tsx`, couleur héritée du parent ; `CATEGORY_META` n'a **plus de champ `emoji`**, et les `<option>` natives affichent le label seul). Un seul style de conteneur (carte blanche `rounded-2xl shadow-sm` sur fond crème, un seul niveau d'inset sage-50 max), pas de bordures pointillées. Émojis conservés uniquement pour le contenu émotionnel (🎉 🎁, états vides). Planification intervalle = une ligne « Tous les [n] jours, à partir du [date] » ; rotation = lignes « J1/J2 » compactes dont le sélecteur n'apparaît qu'au tap sur « + » (state `addingDay`), sans encadré récap ; « Tours du circuit » promu en carte pleine ligne.
- Tailwind v4 : thème en CSS-first dans `src/index.css` (`@theme`), pas de tailwind.config.

## Pièges connus

- Firestore refuse `undefined` → tout passe par `clean()` dans store.ts ; les champs optionnels vidés sont stockés comme `''`.
- `tsconfig` strict avec `noUnusedLocals` : tout import non utilisé casse le build.
- Le bundle dépasse 500 kB (Firebase + Recharts) : avertissement vite normal.
